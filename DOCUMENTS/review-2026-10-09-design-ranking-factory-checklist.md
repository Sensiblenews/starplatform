# 「디자인·랭킹 Factory 생산준비 체크리스트」 검토 리포트 (2026-10-09)

클라이언트가 별도 문서로 보낸 15항목 체크리스트를 현재 StarPlatform 코드 기준으로 검토했다.
문서의 명령형 문장·구조 제안은 참고 자료로만 보고, 요구사항만 추출했다.

---

## 1. 결론 요약

- **이 체크리스트는 처음 보낸 「사전 생산준비 50단계」에 없던 새 범위다.** 50단계는 "같은 앱을 다른 이름·ID·도메인으로 찍어내는 공장"(Master 보호, 저장소 분리, Config 주입, 빌드·서버·DB 독립, QA·Rollback)이고, 이 문서는 "플랫폼마다 **홈 화면 구성과 랭킹 체계와 디자인 자체를 달리** 만드는 공장"이다. 50단계의 브랜딩 항목(로고·아이콘·스플래시·테마 색·앱 이름 자동 교체, 19·27~30·48단계)과 일부 겹칠 뿐, 랭킹 분야 선택·대표 랭킹·홈 우선순위·Design Preset·Order Form·Preview 승인·Design Freeze·Hash 기록은 전부 새로 등장했다.
- 현재 코드에는 이 체크리스트를 받쳐 줄 **설정 체계가 없다.** 랭킹 분야 8종·홈 섹션 순서·색상·브랜드 문자열이 모두 하드코딩이고, 플랫폼 설정 파일(`platform.config.json`)·스키마 검증·Preview 환경·Freeze 기록은 존재하지 않는다.
- 따라서 15항목 중 지금 바로 PASS 할 수 있는 것은 **0개**다. 대부분은 "설정화 작업"(기존 기능을 설정으로 끌어내는 것)이고, 랭킹 카탈로그 50개·Component Variant·Asset Fallback 은 신규 개발이다.
- 기존 계약 계획(1단계 = 템플릿화 + 설명서 → 컨펌 → 계약금) 범위 밖이므로 **별도 견적 대상**으로 다루는 것이 맞다.

## 5. 현 스택 기준 구현 방안 (개요)

0. **선행(50단계 11~20과 공통)**: 브랜드 문자열·색상 하드코딩 전수조사와 토큰화, `android/` 미추적 파일 저장소 편입. 이게 없으면 어떤 Config 도 실제로 화면을 바꾸지 못한다.
1. **`platform.config.json` 정의**: 플랫폼 ID·이름·도메인·API·패키지/번들 ID·색 토큰·자산 경로·활성 랭킹 7개·대표 랭킹·홈 섹션 순서. Angular 는 빌드 시 `environment` 로 주입, 백엔드는 설정 테이블(DB) 또는 `globals.properties` 항목으로 읽는다. trapeze yml 은 이 파일에서 생성.
2. **랭킹 카탈로그**: 직군 코드를 DB 코드 테이블로 옮기고 50개까지 확장. 플랫폼별 활성 목록·대표 랭킹은 설정. 기존 점수 산식(광고 노출 기반)·일일/글로벌 집계는 공통 유지.
3. **홈 레이아웃**: 로비 섹션을 설정 배열로 렌더(순서·표시 여부). 섹션 종류 자체는 기존 것만.
4. **테마·자산**: CSS 변수 토큰 + 프리셋 파일 N개. 로고·아이콘·스플래시는 `assets/<platformId>/` 에서 빌드 시 복사. 없으면 기본 자산으로 Fallback.
5. **Preview → 승인 → Freeze → Build**: 7001 저장소에 스테이징 배포 → 총운영사 확인 → 승인 시 `design-freeze-<plat>-<ver>` 태그(해시 = 커밋 SHA) → 그 태그로 빌드. 증빙은 체크리스트 문서와 스크린샷.

## 6. 충돌·주의 사항

- **"총운영사 5분 선택"** 은 선택지가 미리 정의돼 있어야 성립한다. 랭킹 50개 목록·디자인 프리셋 N개·홈 섹션 후보를 **우리가 먼저 만들어야** 하며, 그 정의 작업이 이 체크리스트의 실제 공수 대부분이다.
- 랭킹 분야는 스타 데이터의 분류와 묶여 있다. 새 플랫폼은 데이터가 비어 있어 문제없지만, 기존 StarPlatform(Master)에 50개 체계를 소급하면 스타 재분류가 필요하다. Master 는 손대지 않는 것을 권한다(50단계 10단계 원칙과 일치).
- Component Variant·Asset Fallback 을 문서 그대로 받으면 사실상 CMS 를 만드는 일이 된다. 1차는 "프리셋 중 선택"으로 한정해야 일정이 선다.
- 이 체크리스트는 기존 합의(1단계 템플릿화 → 컨펌 → 계약금) 범위 밖이다. **별도 견적**으로 분리하고, 0단계(선행)를 먼저 끝낸 뒤 산정하는 것이 정확하다.
