# 2-29차 검토 ③ — 로비 My Global Ranking 카드 + 오프닝 폭죽 + 첫 화면 공간 확보

## 요약

세 덩어리다. ① VS 카드와 Today's TOP 사이에 **My Global Ranking 카드**(로그인/비로그인 두 변형), ② 앱을 켰을 때 로비에서 1.5초 도는 **오프닝 오버레이**(지구본·별빛·파동·문구·햅틱 1회), ③ 카드 자리를 만들기 위한 **VS 카드·Today's TOP 축소**. 순위·점수·조회수·좋아요·즐겨찾기는 이미 서버에 있는 값이라 **새 테이블 없이** 가벼운 API 하나를 추가하면 된다. 유일하게 데이터가 없는 것은 "직전 순위"(▲ 6)이며, 기기 로컬 저장으로 풀면 DDL 없이 가능하다.

## 2. 현 아키텍처 기준 구현 방안

### 2-1. core-backend (Spring 4.1 / MyBatis / MariaDB)

**신규 API 1개 — `GET|POST /api/super/ranking/my-rank`** (기존 엔드포인트 변경 없음)

- 입력: `starId`, `starToken` (기존 `verifyStarToken` 재사용 — 내 정보라 본인 확인 필수)
- 출력: `globalRank`, `totalStars`, `score`, `viewCount`, `likeCnt`, `followerCnt`, `name`, `image`
- 데이터 출처
  - 순위·조회수·전체 수: `StarRankService.getGlobalRankMap()` (이미 Redis 캐시, TTL 10초). 스타 상세 API가 쓰는 `applyGlobalRank`와 같은 방식이라 스타 페이지와 숫자가 일치한다.
  - 좋아요·즐겨찾기: `WH_PRESS.LIKE_CNT / FOLLOWER_CNT` 한 행 조회 (매퍼 1개 추가, superapp.xml)
  - Global Score: `viewCount×1 + LIKE_CNT×3 + FOLLOWER_CNT×5`. **VS 카드·글로벌 순위가 쓰는 정렬식과 동일**하므로 목업의 `pts`와 VS 카드의 `pts`가 같은 단위가 된다.
- 왜 기존 `/api/super/star/{starId}`를 그냥 쓰지 않는가: 피드·갤러리까지 함께 내려오는 무거운 응답이고, 로비 진입마다 부르기엔 과하다. 순위표 밖 페이지(`IS_STAR='N'`)는 `globalRank: null`로 내려 R10을 지킨다.
- 컨트롤러 → 서비스 → 매퍼 순으로 작성. DDL 없음.

**"직전 순위"(R4·R9)는 서버에 없다.** 순위 이력 테이블·스냅샷 스케줄러가 존재하지 않는다. 기본안은 프런트 로컬 저장(아래). 서버 방식(어제 자정 스냅샷 대비)을 원하면 새 테이블 + 스케줄러가 필요하므로 승인 항목으로 분리했다.

### 2-2. core-frontend (Angular 16 / Ionic 8)

**신규 컴포넌트 `pages/lobby/components/my-ranking-card`**

- 입력: 로그인 여부(`isStar && starId`), 위 API 응답
- 로그인 변형: 목업 레이아웃 그대로. `#15` 폰트는 목업 대비 한 단계 작게(R3). 변동 표시는 `▲ 6` / `▼ 3` / 유지 시 표시 없음.
- 버튼: **My Star Page** → 기존 `goToMyStarPage()`, **Top Rankings** → 기존 `toggleRankingList()` (트로피 아이콘과 동일 동작, 랭킹 인라인 섹션 열림)
- 비로그인 변형: 같은 카드 셸에 문구 + **Create My Star Page** 버튼 → 기존 ＋ 메뉴의 "Create a Star Page"(`openAvailablePageModal`) 흐름 재사용. 첨부 이미지가 오면 그 구성에 맞춘다.
- 노출 텍스트는 코드 규칙상 **영어**로 작성한다(클라이언트 예시 문구 "나의 순위는 몇 등일까요?"는 `Where do you rank in the world?`처럼 영어화).
- 순위 변동 기준(기본안): 마지막으로 확인한 순위를 `localStorage`에 `starId`별로 저장하고, 새 응답과 비교해 달라졌을 때만 R9 애니메이션 + `▲/▼ 차이`. 로그아웃·다른 계정 로그인 시 키가 달라 오염되지 않는다. 첫 로드(저장값 없음)는 변동 표시 없음.
- 갱신 주기: 로비 진입(`ionViewDidEnter`) + 당겨서 새로 고침 + 화면에 보일 때 30초 간격. VS 카드처럼 3초 폴링을 붙이면 로그인 사용자마다 초당 0.3건이 늘어 과하다(미결 Q4).
- 기존 스켈레톤(`app-skeleton`)으로 로딩 자리 확보 → 카드 높이 점프 방지.

**신규 컴포넌트 `components/global-opening-overlay`** (오프닝 폭죽)

- `app.component` 수준의 싱글턴 서비스에 "이 프로세스에서 이미 보여줬는가" 플래그를 둔다. 로비 `ionViewDidEnter`에서 플래그가 비어 있을 때만 1회 재생 → 뒤로 가기·탭 복귀로 로비에 다시 와도 재생 안 됨(F1). 앱 프로세스가 죽고 다시 켜지면 플래그가 사라져 다시 재생된다.
- 순수 CSS 애니메이션(지구본 scale, 별빛 opacity/scale 시차, 파동 ring scale+fade, 문구 fade). 파티클 라이브러리·의존성 없음.
- `pointer-events: none`으로 아래 로비 조작을 막지 않음(F9). 1.5초 후 `*ngIf` 해제로 DOM 제거.
- 0.4초 지점에서 기존 `HapticService.tap()` 1회(F6). 이 서비스는 iOS Medium / Android Light, 400ms 쿨다운이 이미 있다.
- `matchMedia('(prefers-reduced-motion: reduce)')`가 참이면 애니메이션 없이 정적 표시 후 같은 시간에 제거, 햅틱 생략(F8). 이 패턴은 `vs-carousel.component.scss`에 이미 있다.
- 백그라운드 전환: 로비에 이미 있는 `appStateChange` 리스너에서 오버레이를 즉시 제거(F8). API 응답과는 완전히 독립(F8).

**VS 카드 축소 (S1~S3)** — `vs-carousel.component.html/scss`

- `side-stats`에서 ❤️·⭐ 줄 삭제, `side-score`(pts) 삭제, `score-gap` 삭제. 게이지(54%/46%)는 그대로 둔다(점수 비율은 서버 값이라 표시 여부와 무관).
- 카드 상·하 패딩 소폭 축소. 2-26차 "지표 3종 각 줄" 결정은 이번 요청으로 대체된다.

**Today's TOP 첫 화면 (S4)** — `lobby.page.html/scss/ts`

- 카드 DOM은 유지하고, 🌍 순위·👁️ 조회수 두 줄을 기본 접힘(높이 0·투명)으로 두었다가 로비 세로 스크롤이 시작되면(`onLobbyScroll` 기존 핸들러, scrollTop > 임계값) 슬라이드로 펼친다. 첫 화면 최하단이 "사진+이름"에서 끊기는 효과가 기기 높이에 관계없이 재현된다. 해석이 맞는지 확인 필요(미결 Q3).

**테스트**: `my-ranking-card`·`global-opening-overlay` spec(순위 변동 계산·1회 재생 플래그·reduced-motion 분기), `vs-carousel` spec 갱신. `npx tsc --noEmit` + `npx ng test`. 백엔드 `./mvnw.sh test`.

## 5. 미결 질문 (클라이언트 회신 필요)

1. **비로그인 카드 이미지**가 메일에 첨부되지 않았다("아래 이미지" 언급만 있음). 이미지 없이는 문구·버튼 배치만 목업 톤에 맞춰 제작한다. 별도 참고 메일("세로 공간 확보", "폭죽 2건") 중 이번 메일에 포함되지 않은 것이 있는지도 확인.
2. **▲ 6의 기준**: 마지막으로 앱에서 확인한 순위 대비(기본안, DB 변경 없음)인지, 어제 자정 순위 대비(테이블+스케줄러 필요)인지.
3. **Today's TOP "스크롤 시 올라오는 형식"**: 로비를 세로로 스크롤하면 순위·조회수 줄이 펼쳐지는 방식으로 이해했다. 맞는지.
4. **카드 갱신 주기**: 진입 시 + 30초 간격(기본안) vs VS 카드처럼 3초 폴링.
5. **폭죽 재생 조건**: 앱을 완전히 종료 후 다시 켠 때만인지, 백그라운드에서 돌아올 때(resume)도 포함인지. 기본안은 콜드 스타트만.
6. **Global Score 정의**: `방문 ×1 + 좋아요 ×3 + 즐겨찾기 ×5`(현 글로벌 순위·VS 점수와 동일)로 표시한다. 다른 정의를 원하는지.
7. 폭죽 문구·비로그인 카드 문구는 코드 규칙상 영어로 낸다. 확인.
8. 대금 제안(총 10, 킥오프 5 / 완료 5)은 개발 범위 외 항목 — 사용자 회신 사항.
