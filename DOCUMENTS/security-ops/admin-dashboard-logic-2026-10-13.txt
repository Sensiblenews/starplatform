================================================================================
 StarPlatform (WITCH) 어드민 메인화면(대시보드) — 항목별 집계 로직 설명
 작성일 2026-10-13 / 대상: 총운영사 운영자·관리자
================================================================================

어드민에 로그인하면 처음 뜨는 화면(대시보드)의 숫자·그래프가 각각 무엇을 어떻게
세는지 적은 문서다. 실제 쿼리를 읽고 그대로 옮겼으며, 숫자를 해석할 때 주의할
점은 각 항목 끝의 [알아둘 점]에 적었다.


--------------------------------------------------------------------------------
 0. 공통 전제
--------------------------------------------------------------------------------

[권한에 따라 범위가 다르다]
  - SM(총괄 관리자): 모든 국가 합산. 제목이 "총괄 현황판 (Global Dashboard)".
  - LC(지역 관리자): 자기 국가만. 제목이 "지역 현황판 (국가코드)".
    "자기 국가"는 로그인한 관리자의 국가 코드로 정해지며, 집계는 "그 국가 소속
    스타의 활동"을 기준으로 자른다. 즉 LC 화면의 DAU는 "그 나라 스타 페이지를 본
    사람 수"이지 "그 나라에 사는 사람 수"가 아니다.

[데이터 출처는 크게 두 테이블]
  - 광고 노출 로그(WH_AD_LOG): 앱·웹에서 스타 페이지를 보거나 광고가 노출될 때
    한 줄씩 쌓인다. 접속자(DAU/MAU), 재방문율, 시청 수, 월별 추이가 전부 여기서
    나온다. 한 줄에는 보는 사람 ID(기기 ID), 스타 ID, 행위(IMPRESSION 등), 시각이
    들어 있다.
  - 계정 테이블(WH_PRESS): 스타 계정과 관리자 계정이 들어 있다. 일반 팬·앱 사용자
    계정은 여기 없다. 등록 스타 수, 신규 가입, 국가별 분포가 여기서 나온다.

[시간 기준]
  - "오늘"은 DB 서버의 날짜(자정 00:00 기준)다. 운영 서버는 한국 시간(KST)으로
    맞춰져 있다.
  - 화면은 자동 갱신되지 않는다. 숫자는 페이지를 연 순간에 계산된다. 최신값을 보려면
    새로고침한다.


--------------------------------------------------------------------------------
 1. 상단 4개 카드
--------------------------------------------------------------------------------

[1-1] DAU (일간 접속)                                                      단위: 명
  무엇을 센다
    오늘(00:00~지금) 광고 노출 로그에 "IMPRESSION"(노출) 행이 한 번이라도 있는
    보는 사람 ID의 개수. 같은 사람이 100번 봐도 1로 센다.
  LC는
    자기 국가 스타의 페이지를 본 사람만.
  알아둘 점
    - 보는 사람 ID는 앱 기기 ID다. 앱을 지웠다 깔거나 기기를 바꾸면 새 사람으로
      센다.
    - 웹(브라우저)에서 스타 페이지를 본 방문자는 전원이 "WEB"이라는 ID 하나로
      기록된다. 그래서 웹 방문자가 1만 명이어도 DAU에는 1로 들어간다. 웹 방문 수는
      별도 지표(방문 카운팅)로 본다.
    - 광고 노출 자체에 1초 중복 방지가 걸려 있어 같은 사람이 연타해도 행이 폭증하지
      않는다.

[1-2] MAU (월간 접속)                                                      단위: 명
  무엇을 센다
    지금부터 30일 전까지(30일 × 24시간, 달력의 "이번 달"이 아님) 광고 노출 로그에
    행이 하나라도 있는 보는 사람 ID의 개수.
  LC는
    자기 국가 스타 기준.
  알아둘 점
    - DAU와 달리 행위 종류를 가리지 않는다. 노출(IMPRESSION)뿐 아니라 공유(SHARE)
      등 다른 행위도 들어간다. 공유 행은 "SYSTEM"이라는 고정 ID로 기록되므로
      MAU에 "SYSTEM" 1명, "WEB" 1명이 더해질 수 있다.
    - 그래서 DAU와 MAU는 정의가 완전히 같지 않다. "DAU ÷ MAU"로 활성 비율을
      계산할 때는 이 차이를 감안한다.

[1-3] 신규 가입 (오늘)                                                     단위: 명
  무엇을 센다
    오늘 계정 테이블(WH_PRESS)에 새로 만들어진 계정 수.
  LC는
    자기 국가 코드로 등록된 계정만.
  알아둘 점
    - 팬·앱 사용자 가입이 아니다. 이 테이블에는 스타 계정과 관리자 계정만 있다.
      따라서 이 숫자는 "오늘 생긴 스타 페이지 + 관리자 계정" 수다.
    - 여기에 포함되는 것: 어드민에서 등록한 스타, 일괄 등록한 스타, 앱에서 자동
      생성된 스타 페이지, 스타가 직접 개설(클레임)한 페이지, 새로 만든 지역 관리자
      계정.
    - 앱 사용자(팬) 증가를 보고 싶으면 이 카드가 아니라 DAU/MAU를 본다.

[1-4] 재방문율 (Retention)                                                 단위: %
  무엇을 센다
    (어제 본 사람 중 오늘도 본 사람 수) ÷ (어제 본 사람 수) × 100. 정수로 반올림.
    "본다"는 노출(IMPRESSION) 행 기준이고, 사람은 보는 사람 ID 기준이다.
  LC는
    자기 국가 스타 기준으로 어제·오늘 모두 자른다.
  알아둘 점
    - "어제 대비 오늘" 하루짜리 지표다. 주간·월간 리텐션이 아니다.
    - 오늘은 아직 진행 중이므로 아침에는 낮고 저녁으로 갈수록 올라간다. 같은 시각에
      비교해야 의미가 있다.
    - 어제 본 사람이 0명이면 0%로 표시된다.
    - 웹 방문자 "WEB" ID는 어제도 웹 방문이 있고 오늘도 있으면 "재방문 1명"으로
      들어간다.


--------------------------------------------------------------------------------
 2. 두 번째 줄 3개 카드
--------------------------------------------------------------------------------

[2-1] 총 등록 스타 (SM) / 지역 등록 스타 (LC)                              단위: 명
  무엇을 센다
    계정 테이블에서 "스타" 유형이면서 "스타" 권한인 계정 수.
  LC는
    자기 국가 코드만.
  알아둘 점
    - 비활성(정지) 처리된 스타도 포함한다. 활성 스타만 세는 숫자가 아니다.
    - 아래 "국가별 스타 분포" 도넛 그래프와 합계가 약간 다를 수 있다(3-1 참조).

[2-2] 총 누적 광고 시청 수                                                 단위: 회
  무엇을 센다
    광고 노출 로그의 전체 행 수. 기간 제한 없음(서비스 시작부터 지금까지).
  LC는
    자기 국가 스타에 대한 행만.
  알아둘 점
    - 행위 종류를 가리지 않는다. 노출(IMPRESSION) 외에 공유(SHARE) 등도 전부 센다.
      따라서 "순수 광고 노출 수"보다 약간 크다.
    - 스타 관리 목록의 스타별 "광고 노출 수"는 노출(IMPRESSION)만 세므로, 스타별
      값을 다 더해도 이 카드와 정확히 맞지 않는다. 정산 근거로는 스타별 값을 쓴다.
    - 웹 랜딩 방문도 노출 행으로 들어가므로 여기 포함된다.

[2-3] 서버 상태 모니터링
  무엇을 보여주나
    - "DB: ON" 배지
    - JVM 메모리 "사용 MB / 최대 MB"와 사용률 막대 (80% 이상 빨강, 60% 이상 노랑)
    - SM에게만 "상세/정리" 버튼 → 시스템 관리 화면으로 이동
  알아둘 점
    - "DB: ON"은 실제 점검 결과가 아니라 "이 화면이 떴다 = DB 조회가 됐다"는 뜻의
      고정 표시다. DB가 죽으면 이 화면 자체가 오류로 안 뜬다. OFF로 바뀌는 경우는
      없다. DB 상태는 시스템 관리 화면이나 경보 센터에서 본다.
    - 메모리 숫자는 페이지를 연 순간의 값이고 자동 갱신되지 않는다. 실시간은
      시스템 관리 화면(5초 갱신)에서 본다.


--------------------------------------------------------------------------------
 3. 세 번째 줄 그래프
--------------------------------------------------------------------------------

[3-1] 국가별 스타 분포 (도넛) — SM에게만 표시
  무엇을 센다
    계정 테이블에서 "스타" 유형인 계정을 국가 코드별로 센다.
  알아둘 점
    - 2-1의 "총 등록 스타"는 유형 + 권한 두 조건이고, 이 그래프는 유형 한 조건만
      본다. 그래서 둘의 합계가 다를 수 있다. 권한이 바뀐 계정이 있을 때 생기는
      차이다.
    - 국가 코드가 비어 있는 계정은 빈 라벨 또는 "null"로 한 조각이 생긴다. 이런
      조각이 보이면 스타 관리에서 국가를 채워 넣는다.
    - 색은 4가지만 지정되어 있어 국가가 5개 이상이면 나머지는 기본 색으로 나온다.
    - 데이터가 없으면 "데이터 없음".

[3-2] 월별 시청 추이 (최근 6개월) (막대)
  무엇을 센다
    지금부터 6개월 전까지의 광고 노출 로그 행 수를 월별로 묶는다.
    라벨은 "04월", "05월"처럼 월만 표시.
  LC는
    자기 국가 스타 기준.
  알아둘 점
    - 2-2와 같이 행위 종류를 가리지 않는다(노출 + 공유 등).
    - "최근 6개월"은 오늘 기준으로 거슬러 올라간 6개월이라, 맨 왼쪽 막대는 월의
      일부만 들어간 "부분 월"이다. 막대가 7개까지 보일 수 있다(예: 4월 일부~10월).
    - 행이 하나도 없는 달은 0으로 표시되지 않고 아예 빠진다. 막대 사이에 달이
      건너뛰어 보이면 그 달은 로그가 없었던 것이다.
    - 이번 달 막대도 아직 진행 중인 부분 월이라 지난달보다 낮게 보이는 게 정상이다.

메뉴는 5개 그룹으로 접혀 있고, 그룹 제목을 누르면 펼쳐진다. 괄호는 볼 수 있는 권한.

  ① 스타 (SM·LC)

--------------------------------------------------------------------------------
 5. 숫자 해석 시 체크리스트
--------------------------------------------------------------------------------

  - DAU가 갑자기 0에 가까우면: 앱 광고 로그가 안 들어오는 것이므로 시스템 관리의
    API 5xx와 DB 상태를 먼저 본다.
  - DAU는 정상인데 MAU가 과하게 크면: 기기 ID가 자주 바뀌는 환경(재설치)일 수
    있다. 추세로만 본다.
  - 신규 가입이 평소보다 크게 튀면: 일괄 등록이나 자동 생성 페이지가 돌았는지
    스타 관리에서 오늘 생성된 계정을 본다. 팬 가입이 아니다.
  - 재방문율은 같은 시각끼리 비교한다. 오전 수치는 항상 낮다.
  - 누적 시청 수·월별 추이는 "로그 행 수"다. 정산용 노출 수는 스타 관리의
    스타별 노출 수를 쓴다.
  - "DB: ON"은 믿지 않는다. DB 상태는 시스템 관리 화면에서 본다.


--------------------------------------------------------------------------------
 6. 개선 후보 (요청 시 반영)
--------------------------------------------------------------------------------

  이 문서를 쓰면서 확인된, 숫자 해석을 헷갈리게 만드는 지점이다. 수정 여부는
  별도 결정 사항이다.
  1. MAU에도 DAU와 같은 "노출(IMPRESSION)만" 조건을 넣어 두 지표의 정의를 맞춘다.
  2. 누적 시청 수·월별 추이에 "노출만" 조건을 넣어 스타별 노출 수와 합이 맞게 한다.
  3. "신규 가입"을 "신규 스타 페이지"로 라벨을 바꾸거나, 관리자 계정을 제외한다.
  4. "DB: ON" 배지를 실제 점검(시스템 관리와 같은 방식) 결과로 바꾼다.
  5. 국가별 분포 그래프에 "스타 권한" 조건을 더해 총 등록 스타와 합계를 맞춘다.
  6. 월별 추이에서 비어 있는 달을 0으로 표시한다.
