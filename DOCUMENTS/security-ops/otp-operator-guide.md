# 총운영사 · 관리자용 Google OTP 이중인증 안내 (2026-10-12)

슈퍼 어드민(SM)과 지역 관리자(LC) 로그인에 Google Authenticator 기반 이중인증(TOTP)이 적용됩니다.
비밀번호가 맞아도 **인증 앱의 6자리를 확인하기 전에는 관리자 권한이 발급되지 않습니다.**
스타(ST) 계정의 `/star/*` 로그인과 앱(API)은 영향이 없습니다.

---

## 1. 최초 1회 — 등록

1. 휴대폰에 **Google Authenticator** 를 설치합니다 (App Store / Play 스토어). Authy, Microsoft Authenticator 도 됩니다.
2. 어드민(`/super/login.do`)에 아이디·비밀번호로 로그인합니다.
3. 등록 의무 대상(SM·LC)인데 아직 등록이 없으면 **OTP 등록 화면**으로 바로 안내됩니다.
   - 이미 로그인된 상태라면 좌측 메뉴 **보안 · 이중인증 → 지금 등록**(비밀번호 재확인) 으로도 갈 수 있습니다.
4. 앱에서 **QR 코드를 스캔**합니다. 카메라를 못 쓰면 "설정 키 입력"을 고르고 화면의 키를 직접 넣습니다 (시간 기반).
5. 앱에 뜬 **6자리를 입력**하고 "등록 확인"을 누릅니다. 등록 화면은 10분 동안만 유효합니다.
6. **복구 코드 5개**가 한 번만 표시됩니다. 종이에 적어 금고에 두거나 비밀번호 관리자에 저장하세요.
   메신저·메일·공유 문서에 두지 마세요. "보관했습니다"에 체크한 뒤 계속을 누르면 로그인이 완료됩니다.

## 2. 매번 로그인

1. 아이디·비밀번호 입력
2. 휴대폰에서 Google Authenticator 실행 → 해당 어드민 항목의 6자리 확인
3. 이중인증 화면에 6자리 입력 → 접속

- 번호는 30초마다 바뀝니다. 앞뒤 30초 오차는 허용됩니다.
- **같은 번호를 두 번 쓸 수 없습니다.** 바로 다시 로그인해야 하면 다음 번호가 뜰 때까지 기다리세요.
- **5회 연속 실패하면 10분간 잠깁니다.** 잠금 중 입력은 실패로 세지 않습니다.
- 번호가 계속 틀리면 휴대폰의 **시간 자동 설정**이 켜져 있는지 확인하세요. 서버는 NTP 로 시간을 맞추고 있습니다.

## 3. 휴대폰 분실 · 교체

### 복구 코드가 있을 때
1. 로그인 → 이중인증 화면의 같은 칸에 **복구 코드**(예: `ABCDE-FGHJK`)를 입력합니다. 대소문자·하이픈은 상관없습니다.
2. 들어온 뒤 **보안 · 이중인증 → 휴대폰 교체 · 재등록**(비밀번호 재확인) 으로 새 기기를 등록합니다.
   재등록이 끝나면 이전 비밀키와 복구 코드는 모두 무효가 되고 새 코드 5개를 받습니다.
3. 사용한 복구 코드는 다시 쓸 수 없습니다. 남은 코드가 1개 이하면 **복구 코드 재발급**(비밀번호 + 현재 OTP)을 하세요.

### 복구 코드도 없을 때
1. 총운영사(SM)에게 **OTP 재설정**을 요청합니다. 사전에 정한 본인 확인(대면·전화 등)을 거칩니다.
2. SM 은 **보안 · 이중인증 → 관리자 이중인증 현황 → OTP 재설정** 에서 사유를 적고 본인 비밀번호를 재확인한 뒤 실행합니다.
3. 재설정되면 그 관리자는 다음 로그인에서 처음부터 다시 등록합니다. 재설정 사유·승인자·시각은 **감사 로그**에 남습니다.
4. 기기 분실 직후에는 **비밀번호도 함께 변경**하고, 감사 로그에서 이상 로그인 시도가 없는지 확인하세요.

> DB 를 직접 수정해 OTP 를 우회하는 임시 조치는 금지입니다. 모든 재설정은 어드민 화면에서 하고 감사 로그로 남깁니다.

### 유일한 SM 계정이 잠긴 경우 (비상 절차)
복구 코드도 없고 재설정해 줄 다른 SM 도 없는 상황을 막기 위해 **SM 계정을 2개 이상**(일상용 + 비상용) 두고,
비상용 계정의 복구 코드는 별도 장소에 보관하는 것을 권장합니다. 그래도 전부 잠겼다면 서버 관리자가 운영 DB 에서
해당 계정의 `WH_ADMIN_MFA` 행과 `WH_ADMIN_MFA_BACKUP_CODE` 행을 삭제하는 것이 마지막 수단이며,
이 경우 실행자·시각·사유를 별도 문서로 남기고 HQ 에 보고합니다.

## 4. 감사 로그 (SM)

좌측 메뉴 **감사 로그**에서 다음을 조회할 수 있습니다. 비밀키·OTP 번호·복구 코드·비밀번호는 기록되지 않습니다.

| 이벤트 | 뜻 |
|---|---|
| LOGIN_SUCCESS / LOGIN_FAIL | 비밀번호 단계 결과 |
| OTP_SETUP_STARTED / OTP_REGISTER | 등록 시작 / 등록 완료(또는 확인 실패) |
| OTP_LOGIN_SUCCESS / OTP_LOGIN_FAIL / OTP_LOCKED | 2차 인증 결과, 5회 실패 잠금 |
| OTP_BACKUP_CODE_USED / OTP_BACKUP_CODE_REISSUED | 복구 코드 사용 / 재발급 |
| OTP_RESET | SM 의 재설정 (대상·사유 포함) |
| ALERT_SETTING_CHANGED / ALERT_ACK / ALERT_TEST_MAIL | 경보 센터 조작 |

## 5. 자주 묻는 질문

- **등록 QR 을 캡처해 두면 되나요?** 안 됩니다. QR 안에 비밀키가 있어 캡처가 유출되면 OTP 가 무력화됩니다. 등록 뒤 캡처는 삭제하세요.
- **여러 명이 하나의 어드민 계정을 쓸 수 있나요?** OTP 를 여러 기기에 넣을 수는 있지만 권장하지 않습니다. 관리자마다 개별 계정을 쓰세요.
- **OTP 를 끌 수 있나요?** SM·LC 는 서버 정책(`otp.mode=required`)으로 의무입니다. 끄려면 서버 설정 변경이 필요하며 HQ 승인 사항입니다.
- **인증 앱 번호가 계속 틀립니다.** 휴대폰 시간 자동 설정 → 그래도 안 되면 복구 코드로 들어와 재등록하세요.

## 부록 — 서버 관리자용 배포 체크리스트

1. 운영 DB 에 `core-backend/db/admin-mfa-audit.sql` 실행 (테이블 3개 생성).
2. `globals.properties` 에 `otp.encryption.key=<32자 이상 임의 문자열>` 추가. 이 값은 Git·메신저에 올리지 않고 서버에만 둡니다.
   같은 파일에 `security.jwt.secret=<openssl rand -base64 64 결과>` 도 추가합니다 (2026-10-13 부터 필수 — 관리자 토큰 서명 키. 없으면 관리자 로그인이 전부 실패하고 기동 로그에 `[JWT] security.jwt.secret 미설정` ERROR 가 남습니다. 값을 바꾸면 기존 관리자 토큰은 무효가 됩니다).
   (선택) `otp.mode=required|optional|off`, `otp.required.auth=SM,LC`, `otp.issuer=StarPlatform Admin`
3. WAS 재기동 → 기동 로그에 `[MFA] 관리자 이중인증 활성` 이 찍히는지 확인. `otp.encryption.key 미설정` ERROR 가 보이면 2번을 다시 확인.
4. 서버 시간 동기화 확인: `timedatectl` (NTP synchronized: yes) 또는 `chronyc tracking`.
5. SM 계정으로 로그인 → 등록 → 로그아웃 → 6자리로 재로그인 → 복구 코드 1개로 로그인 → 잘못된 코드 5회로 잠금 확인.
6. 키를 분실·변경하면 기존 비밀키를 복호화할 수 없어 **전원 재등록**이 필요합니다. 키 백업은 비밀정보 관리 규칙에 따라 보관하세요.
