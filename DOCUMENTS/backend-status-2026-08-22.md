작성일: 2026-08-22

2-19차부터 최근 차수까지 서버에 들어간 작업은 크게 다섯 갈래입니다.

| 갈래 | 핵심 내용 |
|---|---|
| 웹 랜딩 · SEO | 앱 미설치자용 웹 페이지, 검색엔진 대응, AdSense 정책 대응 |
| 방문·노출 집계 | 랜딩 방문 카운팅과 봇·어뷰징 방어 (Redis 기반) |

## 1. Redis — 어디에 어떻게 쓰이고 있는가

Redis는 서버 안에서 세 가지 역할을 합니다.

### 1-1. 응답 캐시 (조회 API 11종)

같은 데이터를 반복해서 DB에서 꺼내지 않도록 결과를 저장해 둡니다.
화면마다 데이터가 바뀌는 속도가 달라 보관 시간을 따로 잡았습니다.

| 대상 | 보관 시간 | 이유 |
|---|---|---|
| 명예의 전당 (역대 왕·TOP100·월간·연간) | 12시간 | 확정된 과거 데이터 |
| 글로벌 랭킹 · 수익 랭킹 · 일간 랭킹 | 10분 | |
| 로비 (Today's TOP 포함) | 1분 | 1분마다 재계산 |
| 직군별 TOP100 | 1분 | 탭 전환 시에만 호출 |
| VS 카드 | 2초 | 앱이 3초마다 갱신하므로 그보다 짧게 |

### 1-2. 봇·어뷰징 방어 (2-20차 · 2-23차)

방문 수와 광고 노출 수가 조작되지 않도록 여러 단계로 걸러냅니다.

| 순서 | 검사 | 기준 |
|---|---|---|
| 1 | 크롤러·봇 판별 | 접속 프로그램 정보로 검색봇·메신저 미리보기봇 등을 집계에서 제외 (정보가 없으면 봇으로 간주) |
| 2 | 체류 시간 | 페이지를 연 뒤 2.5초 미만이면 제외 |
| 3 | 1회용 토큰 | 서명된 방문 토큰, 30분 내 1회만 유효 |
| 4 | IP 제한 | 분당 30회 |
| 5 | 연타 차단 | 1초 |
| 6 | 재방문 인정 간격 | 1시간 |
| 7 | 하루 상한 | 같은 방문자 24회 |

앱 광고 노출(`/api/ad/log`)에도 1초 연타 차단이 걸려 있습니다.
차단될 때도 정상 응답을 돌려주고 집계에서만 빼기 때문에, 외부에서 걸러졌는지 알 수 없습니다.

Redis에 장애가 나면 집계를 멈추지 않고 통과시킵니다(정상 사용자 피해 방지). 이때는 토큰 서명과 체류 시간 검증이 방어선 역할을 합니다.

### 1-3. 관리자 상태 점검

슈퍼 어드민 시스템 패널에서 Redis 연결 상태·키 개수·메모리 사용량을 확인합니다.

> Redis는 서버 내부(127.0.0.1) 전용이라 외부에서 직접 접근할 수 없습니다.

## 2. 검열·신고 관련 — 현재 구현 상태

**AI 기반 자동 검열은 도입되어 있지 않습니다.** 외부 AI 판정 서비스 연동, 금칙어 사전, 자동 숨김 로직 모두 서버에 없습니다.
현재 운영 방식은 "올라온 뒤 신고를 받아 사람이 처리"하는 사후 처리입니다.

| 기능 | 상태 | 설명 |
|---|---|---|
| 댓글 신고 | 구현됨 | 앱에서 사유(스팸/욕설/광고) 선택 후 신고 |
| 관리자 신고 처리 화면 | 구현됨 | 슈퍼 어드민 신고 목록 → 댓글 블라인드 / 기기 영구 차단 |
| 기기 영구 차단 | 구현됨 | 차단된 기기의 신고는 목록에서 자동 제외 |
| 스타별 블랙리스트 | 구현됨 | 스타가 자기 페이지에서 특정 기기 차단 |
| 회원 간 차단 | 구현됨 | 차단 상대의 게시물·댓글이 목록에서 제외 |
| 봇 차단 | 구현됨 | 방문·노출 집계 한정 (위 1-2) |
| HTML 태그 필터 | 구현됨 | 웹 화면 입력값에 스크립트가 섞이는 것을 차단 |
| 스타페이지 개설 승인 | 구현됨 | 신청 → 관리자 승인/반려 (유일한 사전 승인 절차) |
| AI 자동 검열 | **없음** | |
| 금칙어 필터 | **없음** | 앱 안내 문구로만 경고 |
| 게시물·댓글 사전 검수 | **없음** | 작성 즉시 공개 |

### 알아두실 취약 지점

1. **댓글 작성에 내용 검증도, 횟수 제한도 없습니다.** 도배·욕설을 기계적으로 반복해도 서버가 막지 않습니다. 현재의 횟수 제한은 방문·노출 집계 전용입니다.
2. **신고 자체에도 중복 방지가 없습니다.** 같은 대상을 반복 신고할 수 있어, 신고가 역으로 괴롭힘 수단이 될 수 있습니다.
3. **HTML 태그 필터가 앱 API에는 적용되지 않습니다.** 웹 폼 입력만 걸러지고, 앱이 보내는 형식(JSON)은 필터를 지나갑니다. 댓글 본문은 사실상 그대로 저장됩니다.
4. **개인정보처리방침에 아동 성착취물 무관용 정책이 명시되어 있으나, 이를 뒷받침하는 자동 탐지가 없습니다.** 전적으로 신고 후 수동 처리에 의존합니다. 앱스토어·구글플레이 정책 심사에서 지적될 수 있는 부분입니다.

## 3. 차수별 서버 적용 내역

### 2-19차 — 앱 미설치자용 웹 랜딩
- 공유 링크를 열면 앱 대신 웹 페이지가 뜨도록 랜딩 페이지 신설 (게시물·스타 양쪽)
- AdSense 광고 게재
- 안드로이드: 설치 후 원래 보려던 화면으로 이동 (Play 설치 리퍼러 방식)
- iOS 커스텀 스킴 등록, 앱 최초 실행 시 딥링크가 로비로 빠지던 문제 수정

### 2-20차 — 방문 카운팅 · 공유 링크 · 약관
- **랜딩 방문 카운팅**: 방문 검증 API 신설(서명 토큰 + 체류 시간 + 중복 차단). 집계는 기존 광고 로그에 통합되어 방문자 수·수익 추정에 자동 반영
- **공유 URL 단축** 및 구 경로 하위 호환 유지
- **푸시 알림 토글 오류 수정**: 서버 설정값을 앱이 직접 조회하도록 변경 (기존에는 단말 저장값만 읽어 실제 설정과 어긋남)
- **약관·개인정보처리방침을 관리자 화면에서 직접 등록·수정** 가능하도록 신설. 웹과 앱이 같은 DB 내용을 사용
- **AdSense 정책 대응**: 검색엔진용 구조화 데이터, 대표 주소(canonical) 지정, FAQ 섹션, 짧은 페이지 광고 미노출 처리
- **도메인 루트 개편**: 최근 게시물·인기 스타를 담은 허브 페이지로 교체
- **sitemap.xml 자동 생성**: 게시물이 있는 페이지만 포함

### 2-21차 — VS 배틀필드
- 스타 직군 분류 체계 도입 (STAR/CELEB/BRAND/UNIV/CITY/MEDIA)
- VS 카드 테이블 신설, 기본 카드 자동 시드 + 관리자 특별전 등록
- 직군별 랭킹 API 신설
- **점수 산정 통일**: 노출 ×1 + 좋아요 ×3 + 팔로워 ×5 종합점수 (Daily King만 당일 노출 수)
- 관리자 화면 2종 신설: 스타 직군 분류, VS 카드 관리(고정·정렬)

### 2-22차 — 로비 개편
- ORG(단체) 직군 추가 → 8개 직군
- 직군 탭에서도 순위 번호가 전체 기준 실제 글로벌 순위로 나오도록 랭킹 쿼리 수정

### 2-23차 — 방문 카운트 보호막
- 웹 랜딩과 앱 광고 노출 양쪽에 1초 연타 차단 추가
- 재방문 인정 간격 24시간 → 1시간, 하루 24회 상한
- 차단 시에도 정상 응답 (외부에서 판정 여부를 알 수 없게)

### 2-24차 — 딥링크 · 응답 속도 · 스켈레톤
- **딥링크 범위 축소**: 앱이 가로챌 주소를 게시물·스타·피드 상세로 한정. 약관·개인정보처리방침은 웹에서 열리도록 제외. iOS·안드로이드 설정 파일과 앱 파서 모두 동일 기준으로 정리
- **읽기 전용 API 9종을 GET 방식으로 전환** (기존 POST도 계속 동작 — 구버전 앱 호환). CDN 엣지 캐시를 걸 수 있는 형태가 되어, 적용하면 사용자 요청이 서버까지 오지 않고 가까운 지점에서 응답됩니다
- 로딩 중 빈 화면 제거 (스켈레톤 UI)

### 2-25차 — 로비 후속
- Today's TOP 선정 기준을 24시간 누적 방문자 수로 교체, 자동 11명 + 관리자 지정 5명
- VS 카드 노출/숨김 제어 추가
- 약관 줄바꿈 처리: 평문을 붙여넣어도 줄바꿈이 유지되도록 웹·앱 양쪽에 적용

### 상시 동작 중인 자동 작업
- **빈 스타페이지 재고 유지**: 10분마다 국가별(KR/JP/GB/US/FR/DE) 빈 페이지가 50개가 되도록 부족분만 자동 생성
- **서버 지표 수집**: 5분 / 30분 / 매일 자정 (아래 4번)

## 4. 서버 모니터링 (Cost Guard 요청 선행 작업)

트래픽·비용 판단 근거를 먼저 확보하기 위해 슈퍼 어드민 시스템 패널에 지표를 추가했습니다.

- 5분 주기: 네트워크 송수신량, 요청 수, 응답 용량, 디스크 증가 추세
- 30분 주기: 디렉터리별 용량
- 매일 자정: 일일 누적 초기화
- 상태 화면에 GC·톰캣 스레드/세션·파일 핸들·DB 커넥션 풀·Redis 정보 추가
- 24시간 추이 차트

> 수집 기능은 설정 한 줄로 즉시 끌 수 있습니다. 24시간 이력은 서버 메모리에만 보관하므로 서버 재시작 시 초기화됩니다.

## 5. 배포·확인이 필요한 항목

| 항목 | 상태 |
|---|---|
| VS 카드 노출 제어 DDL | **WAR 배포 전에 DB에 먼저 적용해야 함** (순서가 바뀌면 VS 카드 조회가 실패) |
| ORG 직군 시드 SQL | 적용 여부 확인 필요 (재실행 금지) |
| 최신 WAR 배포 | 운영 API 실측상 ORG 직군 반영 이전 버전으로 보임 — 재확인 요청 |
| **AdSense 광고 코드** | **승인 심사용으로 임시 제거된 상태 — 승인 후 복원 필요** |
| iOS 링크 설정 파일 응답 형식 | Cloudflare 규칙으로 처리 예정 (대시보드 작업) |
| CDN 엣지 캐시 규칙 | 적용 대기 (별도 안내 문서 있음) |
| 앱 링크 설정 변경 | 기존 설치 사용자에게는 재설치 또는 다음 스토어 배포 후 반영 |

## 6. 다음 차수 후보 — 서버 점검에서 나온 항목

기능 요청과 별개로, 이번 점검에서 확인된 손볼 가치가 있는 부분입니다.

**안정성**
1. **Redis 장애 시 주요 화면이 전부 오류가 됩니다.** 캐시 조회가 실패하면 DB에서 직접 읽어오면 되는데, 현재는 그대로 오류로 이어져 로비·랭킹·VS가 동시에 멈춥니다. 캐시 실패를 무시하고 통과시키는 처리 한 곳만 넣으면 해결됩니다. (권장 1순위)
2. **내 수익 조회 캐시에 인증 정보가 빠져 있습니다.** 같은 스타 ID에 대해 먼저 들어온 응답이 10분간 재사용되어, 잘못된 인증으로도 수익 데이터가 보이거나 반대로 본인이 10분간 막힐 수 있습니다.
3. **관리자용 캐시 초기화 수단이 없습니다.** 명예의 전당은 12시간 보관이라 데이터를 고쳐도 반영까지 기다려야 합니다.
4. **사용하지 않는 실시간 점수 데이터가 계속 쌓입니다.** 광고 노출마다 Redis에 점수를 더하고 있으나 이 값을 읽는 곳이 없고(랭킹은 DB에서 계산), 만료 설정도 없습니다.

**어뷰징·검열**
5. **댓글 작성·신고에 횟수 제한을 추가**할지 결정이 필요합니다. 현재는 무제한입니다.
6. **금칙어 필터** — 서버에서 단어 목록 기반으로 거르는 방식은 외부 서비스 없이 구현 가능합니다. 목록 관리 화면을 관리자에 붙일지 함께 정해야 합니다.
7. **AI 자동 검열** — 도입하려면 외부 서비스 계약·비용·오탐 시 처리 정책이 함께 결정되어야 합니다. 별도 논의 사항입니다.
8. **일반 API 요청 제한** — 필요하면 CDN 규칙 신설 건입니다.

## 7. 회신이 필요한 미결 사항

1. KT 서버 상품이 트래픽 종량 과금인지 정액인지 (Cost Guard 방향이 갈립니다)
2. 서버 SSH/관리자 권한 보유 여부
3. Cloudflare 도입 승인 여부
4. 트래픽 절감이 필요할 때 줄여도 되는 기능 범위 (방문 집계는 정산 근거라 제외 권장)
5. 웹 푸터 사업자 정보 (상호·대표자·주소) — AdSense 신뢰도 항목
