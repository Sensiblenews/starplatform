# 2-26차 배포 검증 체크리스트

소요: 30~40분 · 우선순위 순서대로 진행

## 준비물

- 앱 기기 **2대** (또는 앱 1대 + 다른 기기) — 작성자와 타인을 구분해야 한다
- 어드민 계정 (SM 권한), 스타 계정
- 서버 SSH, DB 접속

> 파일 검증(위장 파일·용량·해상도)은 단위 테스트 21건이 이미 덮고 있다. 기기에서 다시 볼 필요는 없다.
> 여기서는 **테스트가 확인할 수 없는 것** — 접근 권한, 파일 이동, 화면, 체감 속도 — 만 본다.

# 0. 배포 직후 (회귀) — 여기서 걸리면 즉시 롤백

가장 먼저, 가장 빨리 확인할 것. **기존 게시물이 사라지는 것**이 이번 변경의 최악 시나리오다.

```bash
mysql -u <user> -p WITCH -e "SELECT MDR_STATUS, COUNT(*) FROM WH_CONTENT GROUP BY MDR_STATUS; SELECT MDR_STATUS, COUNT(*) FROM WH_STAR_CONTENT GROUP BY MDR_STATUS;"
```

- [ ] 두 테이블 모두 **`APPROVED` 한 줄만** 나온다 (`PENDING`이 섞여 있으면 즉시 중단)

앱에서 (로그인 없이, 새 기기 기준):

- [ ] 로비가 정상적으로 뜬다 — Today's TOP, VS 카드, TOP 100, Global Ranking 모두 채워짐
- [ ] 스타 페이지 진입 → 기존 피드가 그대로 보인다
- [ ] 콘텐츠 탭(fairy/goblin/witch/monster) → 기존 글과 썸네일이 그대로 보인다
- [ ] 콘텐츠 상세 진입 → 정상
- [ ] 검색 → 결과가 나온다

> 하나라도 비어 있으면 DDL이 WAR보다 늦게 적용됐을 가능성이 높다.

# 1. 파일시스템 게이트 (보안 핵심)

승인 전 파일이 웹으로 새지 않는지가 이번 설계의 전부다.

**스타 계정으로 앱에서 이미지 글 1건 작성** 후:

```bash
ls -la /var/lib/tomcat7/moderation/pending/ | tail -5
```

- [ ] 방금 올린 파일이 `pending/`에 있다
- [ ] 같은 파일이 `webapps/img/`에는 **없다**

```bash
ls /var/lib/tomcat7/webapps/img/ | grep <위에서_본_파일명>
```

- [ ] 위 명령이 아무것도 출력하지 않는다

브라우저에서 `https://witch-hunting.com/img/<파일명>` 직접 접근:

- [ ] **404가 뜬다** (이미지가 보이면 게이트가 뚫린 것 — 즉시 중단)

# 2. 접근 매트릭스 (기능 핵심)

기기 2대로 확인한다. **작성자 = 글을 올린 계정, 타인 = 다른 기기**.

## 2-1. PENDING (승인 대기)

| 대상 | 기대 |
|---|---|
| 작성자 | 이미지가 **보인다** + "Under review" 배지 |
| 타인 | 게시물은 보이되 이미지 자리에 **"Under review"** |
| 어드민 | 검수 목록에 뜨고 미리보기가 보인다 |

- [ ] 작성자 기기: 자기 글의 이미지가 정상적으로 보인다
- [ ] 작성자 기기: 이미지 좌상단에 "Under review" 배지가 있다
- [ ] 타인 기기: 그 게시물이 목록에 **보인다** (사라지면 안 됨)
- [ ] 타인 기기: 이미지 자리에 "Under review" 안내가 뜬다 (깨진 이미지 ✗)
- [ ] 어드민 → 이미지 검수: 해당 건이 목록에 있고 **썸네일이 보인다**
- [ ] 어드민: "검수 대기" 카운터가 1 이상

## 2-2. APPROVED (승인)

어드민에서 **[공개]** 클릭:

- [ ] 목록에서 해당 행이 사라진다
- [ ] 파일이 `webapps/img/`로 **옮겨졌다**

```bash
ls /var/lib/tomcat7/webapps/img/ | grep <파일명> && ls /var/lib/tomcat7/moderation/pending/ | grep <파일명>
```
(앞은 나오고 뒤는 안 나와야 한다)

- [ ] 타인 기기에서 새로고침 → **이미지가 정상적으로 보인다**
- [ ] 작성자 기기: "Under review" 배지가 사라진다

## 2-3. REJECTED (검수 거절)

새 이미지 글을 하나 더 올리고, 어드민에서 **[거절]** + 사유 입력:

- [ ] 타인 기기: 게시물이 **목록에서 사라진다**
- [ ] 작성자 기기: 게시물이 **사라진다** (거절은 작성자도 못 본다)
- [ ] 파일이 `moderation/hidden/`으로 옮겨졌다 (삭제되지 않았다)

```bash
ls /var/lib/tomcat7/moderation/hidden/ | tail -3
```

## 2-4. 서명 토큰 즉시 무효화 ★

이번 설계에서 가장 자랑할 만한 부분. **거절 즉시 작성자 접근이 끊기는지** 본다.

1. 새 이미지 글 작성 (PENDING)
2. 작성자 기기에서 이미지가 보이는 것 확인
3. **앱을 그대로 둔 채** 어드민에서 [거절]
4. 작성자 기기에서 화면 새로고침(당겨서 새로고침)

- [ ] 게시물이 사라진다 — 이미 발급된 토큰이 통하지 않는다

> Presigned URL 방식이었다면 만료(10분)까지 계속 보였을 자리다.

## 2-5. 남의 대기 이미지 접근 차단

- [ ] 타인 기기의 개발자 도구/네트워크에서 `/api/super/media/pending?t=` 요청이 **없다**
      (작성자에게만 토큰이 내려간다)

# 3. VS 카드 깜빡임

로비에서 VS 카드를 **최소 30초** 지켜본다 (3.5초 × 8회 이상).

- [ ] 카드가 바뀔 때 아바타가 사라졌다 다시 나타나지 **않는다**
- [ ] 전환이 뚝 끊기지 않고 자연스럽게 겹쳐 바뀐다
- [ ] 카드 높이가 전환 때 튀지 않는다

**앱을 완전히 종료 후 재실행** (첫 로딩 확인):

- [ ] 스켈레톤 → 실제 카드로 바뀔 때 **크기와 배경색이 튀지 않는다**
      (예전에는 밝고 짧은 박스 → 어둡고 큰 카드로 점프했다)

- [ ] 좌우 스와이프로 넘겨도 부드럽다

# 4. 스타페이지 복귀 깜빡임

1. 스타 페이지 진입
2. **아래로 한참 스크롤** (피드 5개 이상 지나가게)
3. 콘텐츠 하나 탭 → 상세 진입
4. 뒤로가기

- [ ] 스크롤 위치가 **그대로 유지**된다 (맨 위로 튀지 않음)
- [ ] 피드 이미지가 다시 로딩되지 않는다 (스피너가 다시 돌지 않음)
- [ ] 스켈레톤이 다시 뜨지 않는다
- [ ] 화면이 한 번 하얘졌다 돌아오지 않는다

# 5. 피드 페이징

피드가 **15건 이상**인 스타 페이지에서:

- [ ] 처음에 10건 정도만 로드된다
- [ ] 아래로 스크롤하면 로딩 스피너와 함께 다음 건이 이어 붙는다
- [ ] 이어 붙을 때 **위쪽 이미지가 다시 로딩되지 않는다**
- [ ] 끝까지 내리면 스피너가 더 이상 나오지 않는다

# 6. Android 로딩 시간 (계측)

Android 기기에서 개발자 도구(Chrome `chrome://inspect`)를 연결하고:

```js
localStorage.setItem('perfTrace', '1')
```

**앱을 완전히 종료 후 재실행** → 로비 → 스타 카드 탭.

콘솔에 표가 하나 출력된다.

- [ ] `[perf] 스타페이지 진입 — 총 ___ms` 를 기록한다: **______ms**
- [ ] 구간별 수치를 기록한다 (어디가 오래 걸리는지)

| 구간 | 목표 |
|---|---|
| lobby:navigate → star:api-response | 500ms 이하 |
| 총계 | **2000ms 이하** |

2초를 넘으면 어느 구간인지 알려주시면 그 지점을 다시 봅니다.

측정이 끝나면 끄기:

```js
localStorage.removeItem('perfTrace')
```

- [ ] 저사양 Android 기기에서도 한 번 (있다면)
- [ ] iOS에서 회귀가 없는지 (느려지지 않았는지)

# 8. 어드민 화면

- [ ] 사이드바에 "이미지 검수" 메뉴가 있다
- [ ] 탭 4개 전환이 된다 (검수 대기 / 검수 거절 / 신고 블라인드 / 최근 승인)
- [ ] 카운터 숫자가 실제 건수와 맞는다
- [ ] "가장 오래 기다린 건" 시각이 표시된다
- [ ] 썸네일 클릭 시 새 탭에서 원본이 열린다
- [ ] 처리 후 해당 행만 사라진다 (전체 새로고침 ✗)
- [ ] **어드민 공지**를 이미지와 함께 작성 → 검수 대기에 뜨지 **않는다** (대상 제외 확인)

처리 이력 확인:

```bash
mysql -u <user> -p WITCH -e "SELECT * FROM WH_MEDIA_MODERATION_LOG ORDER BY LOG_ID DESC LIMIT 10;"
```

- [ ] 업로드(PENDING)와 처리(APPROVED/REJECTED) 이력이 모두 남아 있다
- [ ] 관리자 처리 건에 `ADMIN_ID`가 기록돼 있다

# 문제 발생 시

**롤백**: 이전 WAR로 되돌린다. **DDL은 되돌리지 않는다** — 컬럼이 남아 있어도 이전 WAR는 참조하지 않으므로 정상 동작한다.

**증상별 1차 확인**

| 증상 | 볼 곳 |
|---|---|
| 기존 글이 안 보임 | `MDR_STATUS` 분포 (0번) |
| 업로드가 실패함 | `moderation/pending/` 쓰기 권한, 톰캣 실행 계정 |
| 작성자에게 이미지가 안 보임 | 응답에 `pendingImageToken`이 있는지, `starToken` 전달 여부 |
| 승인해도 안 보임 | `webapps/img/`로 파일이 옮겨졌는지 |
| 어드민 미리보기가 깨짐 | SM 권한, `moderation/pending/` 읽기 권한 |
